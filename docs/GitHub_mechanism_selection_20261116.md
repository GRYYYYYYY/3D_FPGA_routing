[开发分流原型](../research/dac_v14_20261112/recommend_current_mechanisms_v1.py)分别处理：

- 共享：当前跨层冗余、保留替代源与余量筛选允许提出同范围 native/domain 连接组，不预测其最终收益。
- 资源 owner：依据可避免的跨层冗余、容量证书与目标/owner 余量提出联合范围，不要求先有正 CPD 收益。
- 时序 owner：需要同一个有正物理延迟收益的见证被容量阻塞。独立的正收益数量与冲突数量不能冒充它们的交集。
- 失败释放：仅在真实 guided 搜索失败时释放该网，保持其他私有树、已恢复分支和域；禁止同一事务重复释放该网。
- 接受与终结：完整组合仍须通过原固定预算和合法性门槛；零当前切口不代表全局最优或研究终止，合法候选档案仍供终结选点和后续时序阶段使用。
