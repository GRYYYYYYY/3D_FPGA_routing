## 2. 修改 A：只切换共享决策的干净对照

保留 `VPR_H3D_MODE=static`，增加独立的内部 assignment 开关，默认保持现有实现。不得把已有 `MODE=candidates` 直接用于这项消融。

对两条实验臂，先生成相同的全局候选表、叶节点及成本，再分支：

- `F`：现有共享/拆分 DP。
- `N`：逐 sink 从相同叶候选中选一项，最小化 `opening(c) + branch(i,c)`，使用固定的并列选择规则。

原共享 DP 的问题是共享资源在同一组内只计一次 opening；独立选择按各连接自身成本决策。新对照只改变这个共享/拆分决定。

必须相同：候选生成与空间多样化、全局 pool、叶的可行性/有限成本过滤、K、评分、关键度门槛、引导权重、源/汇延迟预算、缓存寿命、规划次数、布局、RRG、seed 和详细路由集成。不要给 N 使用 sink 原始局部候选表，而 F 使用扩大后的全局 pool。

新控制位置：R1 补丁中 `H3dFastPlan::plan()` 构造 `leaves/openings` 后、调用 `h3d_plan_partition()` 的位置。现有 static guide-cache guard 在 `h3d_routing.cpp` 的 plan 入口，应保留。

当现有算法因高扇出（>128 eligible pins）或不可行 DP 采用回退时，两臂执行相同回退，保留计数并单列解释，避免把回退差异当作 DP 效应。对可以正常执行两种赋值的连接，两臂均输出一个 preferred candidate。

开发时对相同规划调用记录候选表/叶成本的规范化摘要、选择结果、共享组数和规划次数。完整 trace 用于功能核对；正式计时不打开大量逐连接 trace。

主要指标：成功率及完整状态矩阵；CPD 配对差异；最终 route 使用的跨层资源、每个 net 的共享情况和线长；规划与总体时间。DP 给出的代理目标较好并不自动意味着最终 CPD 较好，二者分别报告。

## 3. 修改 B：跳过不可能触发完整双侧评分的反向查询

源码中的完整 delay 分支要求：当前候选中同时拥有 source 端和 sink 端距离的候选数量，至少达到 `need=min(K, ranked.size())`。

在执行 sink 反向查询前，计算：

```
available = ranked 中已经拥有 source 端距离的候选数量
need      = min(candidate_count, ranked.size())
```

完整双侧覆盖集合一定是 source 已覆盖集合的子集。因此，当 `available < need`，现有分支在本次 source 预算下必定不会使用完整双侧评分。可以省掉反向查询，沿用完全相同的原回退评分、排序和后续 DP。

实现要求：仅在原 `forward && !forward->empty() && !ranked.empty()` 分支内包住 reverse 查询块；跳过时递增原 `unmeasured_pins_` 及新 `reverse_gate_skips_`。**不能通过 continue 跳过整个 sink**，后续候选排序、pool 和 DP 均须执行。计算 available 可在达到 need 后提前停止。

本地源码支持的等价条件：延迟缓存仅按 endpoint 和方向索引；没有 LRU、目标候选参数或跨查询总预算；图、边权和每次查询预算静态。因此省略缓存预热不应改变以后对相同端点的距离结果。服务器最新版必须重新核对这些条件。

重要限定：调试 oracle 目前只验证前若干次查询，省略查询会改变它覆盖的端点。应对固定验证端点单独运行 oracle，再关闭这类重型验证进行计时。程序在超时或内存不足时的终止状态也可能改变，所以不宣称所有文件逐字节等价。

### 验证与推广条件

1. 关闭新开关时复现冻结参考行为。
2. 开启时比较候选偏好、最终真实 route tree 的规范化摘要、CPD、线长及 FULL/独立合法性审计。文件头路径和时间可按明确规则分离，不能去掉实际路由内容后比较哈希。
3. 有效输出差异一旦出现，停止推广该等价优化，定位原因；继续采用已验证的原实现完成机制消融。不要把差异解释成“更优的等价实现”。
4. 记录省略次数、实际 forward/reverse cache-miss queries、settled nodes、cache hits/大小、规划秒数及完整 route-process 时间。省略一次 cache hit 不等于少执行了一次 Dijkstra。
5. 若开发集省略次数为零，或者实际没有减少开销，结束该优化分支，记录原因。本轮不改为扩大预算或换搜索算法。

这项优化的预期是减少相对旧 R1 的无效工作；它不提高双侧评分覆盖率，也不承诺 CPD 改善或相对原生 A0 的整体加速。

## 4. 参数一致的 delay 对照与机制解释

新增 `G`：仅将完整方法的 candidate-cost 从 delay 改为 geometry，其他参数使用同一套冻结值。Hybrid-O 的 b132 参考为 K=16、miss=2、opening=16、delay_budget=4096、min_criticality=0.7；以服务器最终版本核对后的配置为准。SB 的已选 R1 使用 geometry，本来没有 delay 贡献，因此不重复安排等价的 G 运行。

已有“分别调优后的 geometry 最佳配置 vs delay 最佳配置”回答的是配置选择问题，不能替代本项单因素对照。

记录并区分：

- eligible、跳过、完整双侧评分、仅 source 距离参与回退、完全几何回退；
- 候选偏好是否改变、最终 route 是否采用相应跨层资源；
- 关键度加权的双侧覆盖率；
- 若记录了最后路由连接到时序路径的映射，分析真正位于关键路径的连接；否则明确关键路径归因尚未建立。

个案选择先固定规则：现有结果中的最大改善、最大退化及一个持平案例，用于解释机制，明确它们不是总体效果估计。以已记录数据优先，不为获得好看的案例反复跑 seed。

## 5. 具体实验矩阵和预算

所有新增执行使用独立目录，建议 `results/dac_supplement_20261112/`。所有新输入、配置、执行次序在开始确认阶段前记录哈希；原冻结研究结果不覆盖。

角色：`F`=冻结完整 R1；`N`=独立 top-1；`G`=仅关闭 delay；`E`=F 加查询省略。确认阶段 `F_star/N_star/G_star` 共用同一个已验证的查询省略开关：通过功能门则启用，否则三者均关闭。`F_star` 仍须与原 F 核对，不能因代码相似就假定等价。

| 阶段 | 条件 | 角色 | 预定角色数 |
|---|---|---|---:|
| 开发和功能门 | 6 个既有 training 电路；Hybrid-O、P0、W100、seed11 | F/N/G/E | 24 |
| 固定配置后确认 | 6 个确认电路 × SB/Hybrid-O × seed21/23；P0、W100 | F_star/N_star | 48 |
| delay 单因素确认 | 同上其中 Hybrid-O 12 个条件 | G_star | 12 |
| 正式计时 | spmv、softmax；Hybrid-O、P0、W100、seed11；每角色3次 | A0/F/E | 18 |
| **合计** | | | **102** |

开发电路：`attention_layer,bnn,eltwise_layer,gemm_layer,softmax,spmv`。

确认电路：`clstm_like.small,clstm_like.medium,conv_layer_hls,robot_rl,reduction_layer,tpu_like.small.os`。这些电路已经被观察，本矩阵用于有界机制确认，明确带有既有数据暴露，不证明全基准泛化。该选择兼顾之前已有的改善、退化与持平情况，不在本轮根据 N/E 的结果继续删改。

102 是预定角色运行额度；完全等价的既有 QoR 结果可复用，实际新调用可能更少。确认阶段额外预留最多 24 次匹配 A0 的补跑，**整轮 VPR route 调用上限 126 次**。额外开销或基线缺失超出上限时，按预先登记的优先级保留完整对照组并报告缺失，不暗自扩大队列。

旧 QoR 复用条件：网表、placement、RRG、时序模型、seed、路由参数、预算、二进制/行为依据及合法性审计匹配。重新布局、不同宽度 RRG 或有行为变更不能当同一对照。F_star 在最终确认上与冻结 F 的核对需要可用的参考结果；参考缺失时先使用原 F，不跳过等价验证。

正式计时的 18 次一律在同一轮环境重新运行。三个角色按预先登记的轮换顺序串行，报告每次原始值、中位数和范围。不能将新时间直接除以历史共享主机上的时间。

沿用每个 VPR 单线程约束与真实线程验证；非计时任务只有在内存/磁盘预算允许时最多 3 并发。计时窗口内不要并发本研究其他负载，记录共享主机限制。不能以物理机 1.5 TiB 推断容器可用内存。优先复用现有 verified runner 和 seccomp/no-ptrace 计时保护。

每次 route 沿用 1800 秒上限，最大迭代等参数保持原协议。在 102–126 次全部用满 route 上限的预算模型下，累计 route 进程时间约 51–63 小时；若非计时3并发、18次计时串行，route 调用阶段约23–27小时。**这不是总墙钟上界**：构建、布局缺失、哈希、审计、I/O、排队和主机争用另计。安排2–3天执行窗口，每阶段根据实际中位数/p90更新时间估计。时间到即保留部分完成的真实状态。

## 6. 宽度和布局诊断优先复用已有工作

读取最终 paired-width 的 24 个 case、内部 W100/W300 结果和独立审计。对每个 case，确认跨宽度使用同一网表和 placement；不同宽度的 RRG 本来不同，只要求同一宽度内对照匹配，且相同架构生成规则。

输出成功率与 CPD/资源/时间的配对表，包括“两个宽度都合法”“仅W300合法”“仅W100合法”“都未合法”。这描述的是固定预算下的路由结果，不证明数学不可路由性，也不是最小可路由宽度。

比较 W100/W300 时只在各自相同条件下计算 F/A0 的效果，再讨论宽度交互。不要将因 placement 改变导致的差异写成宽度效应。现有 P1/宽度结果不能自动证明新 N 消融在 P1 上同样成立；明确本轮 DP 新确认只覆盖 P0/W100。

本轮默认不新增全宽度扫描。原诊断未完成时列出确切缺口和剩余预算，按科研价值安排原定工作，不重新启动整个协调器。

## 7. 分析方法和论文可用表图

主要比较固定为 F_star vs N_star（DP贡献）、F_star vs G_star（delay贡献）、E vs F（查询省略开销），并保留 A0 背景基准。

每张效果表先给完整预定样本的状态，再给双方合法配对上的条件性 CPD 改善。失败、超时和缺失不能用零值填充，也不能从总体悄悄删除。单次 CPD 改善定义为 `(reference-new)/reference`。

沿用原研究的种子内/电路间聚合口径，并明确配对集合。若给置信区间，以电路为重采样单位并保留同一电路的所有 seed/架构记录；6 个确认电路样本很少，区间仅作不确定性描述，不能把所有 seed×架构当独立样本。

建议最终正文使用：

1. 主实验与完整成功覆盖表：原冻结结果更新到服务器最终状态。
2. 机制消融表：同参数的 F/N/G，CPD、成功数、共享资源及规划开销。
3. 运行时间分解：初始化/延迟查询/DP/详细路由/完整 route-process；E相对F与A0分别报告。
4. 固定 placement 宽度图：同一输入的W100/W300效果与失败状态。
5. 一张机制示意或个案图：展示偏好如何影响实际跨层资源和关键路径；仅有相关性时不写因果。

若 DP 没有额外收益，减少“共享DP带来主要性能提升”的主张；若 E 降低了相对 F 的开销但仍慢于 A0，准确写成降低所提方法的额外开销；若 delay 没有稳定贡献，不把局部最优案例归因于精确 delay 评分。
