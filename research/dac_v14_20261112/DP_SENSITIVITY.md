# Fixed-hierarchy exclusion sensitivity (development diagnostic)

The sealed local-margin trace has 109/250 locally worse chosen events at weight2 and93/229 atweight1, all on co-assigned candidates. The initial149events are identical. A per-leaf independent-score gap would discard many sharing choices, despite earlier evidence that independent refresh loses eltwise CPD benefit. These event counts are not independent trials and do not establish physical delay confidence.

For fixed hierarchy node v, retain its original optimum D(v), and its cheapest two shared-candidate costs S(v,c). For a requested exclusion (leaf i, selected candidate c), the modified optimum at that leaf is its cheapest allowed candidate except c. Walking from i to the root, the new split cost combines the modified child with the unchanged sibling; the new shared cost is the best common candidate except c. Their minimum is the modified optimum. Only ancestors can change. Two cheapest distinct common candidates suffice, including equal-cost alternatives. The final root increase is the exact exclusion margin for this finite shared/split model, not a physical Tdel or STA bound. Infinite exclusion means only that this finite table has no alternative.

The standalone prototype rebuilds table/hierarchy summaries once, then visits O(log n) ancestors per exclusion. It does not perform one full DP solve per leaf, query the RRG, or modify candidate ranking. Current diagnostic overhead still includes the extra summary construction; it must be measured and, if useful, integrated with the existing DP's intermediate results before production promotion. Existing high-fanout independent fallback is outside this diagnostic.

1000 randomized finite tables, 20187 exclusions were checked against deleting the specified candidate and re-running the original partition solver, including1718 infeasible and14872 tied exclusions. A deterministic counterexample has a locally worse selected candidate but positive net-level exclusion margin. Both optimized and address/undefined-behavior sanitizer builds pass. Inputs, code and result hashes are bound in partition_sensitivity_validation_binding.json. This is unit validation, not native or quality validation.

Native trace integration is diagnostic-only and separately opt-in. It compares reconstructed basecost to original plannedcost, records exclusion costs and its own computation time, and preserves all existing scores/guides/queries/transactions.
