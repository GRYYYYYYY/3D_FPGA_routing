# Portable whole-transaction development entry

Current package: `../standalone_transactions_dev_02`. It extends the portable observation/selection package with an explicit native transaction worker, original scope/domain auditors, actual installed-candidate materialization, and a fixed-root resource decision entry. It is not the full frozen confirmation method.

The entry is:

```sh
python transact.py --inputs native-inputs.json --state CURRENT_STATE \
  --root-state ORIGINAL_ROOT --selection CURRENT_SELECTION \
  --output NEW_TRANSACTION --kind owner --domain-mode unrestricted \
  --seed-order delay_rr_id --prepare-only
```

The descriptor uses `standalone_native_observation_input_v1`. Physical files, binary, graph cache and analysis arguments are explicit and digest-bound. Current/root states must have complete native traces, compatible endpoint/constraint identities, matching physical inputs, and native FULL/independent audit receipts. Selection must bind that same current route/vector/trace. Owner preparation reconstructs the request from the current capacity certificate and current-STA screens; no historical transaction template is read. The original root CPD and resource envelope remain fixed, including the existing 0.1% wire allowance.

Removing `--prepare-only` invokes an empty-request source serialization control and the real native request, then scope/domain checks, installed-candidate physical verification, and whole-transaction acceptance or source retention. The calling scheduler must own the shared serial slot. This actual execution path is implemented but **has not yet been exercised with new VPR calls**. Native calls have their existing 1800-second and 64-GiB guards; reported transaction cost is not full algorithm cost. The complete controller, terminal selection and independent confirmation still need integration.

Completed evidence:

- Original two-arm R1 owner protocols were replayed outside the project with Python historical-project reads forbidden. Native queries, attempts, retained scope, reconstructed candidate bytes, full endpoint vector and physical audit content match exactly. Only audit path fields and measured audit duration are excluded from the audit-content equality comparison; hashes and all scientific fields remain compared.
- Candidate materialization retains the original function AST. Native installed-candidate/restoration gates retain their original AST. Version 2 changes only explicit admission of two existing R1 flags, each fixed to `off`: `--routing_failure_predictor` and `--merge_constant_generators`. It neither strips these flags nor accepts arbitrary values.
- Preparing the current owner transaction produces the same five-connection request. The worker executes actual preparation through descriptor checks, private inputs, current binary library binding and command construction, then a clearly marked test capture stops before `io.run`; zero VPR calls occurred.
- Altered actual-candidate gate and a different whole candidate tree are rejected before materialized output creation.

Imported receipt relocations retain original receipt bytes and explicit origin hashes. They are not represented as new native runs. The first audit-dictionary comparison failure and the fixed-option admission failure are preserved in validation versions 1 and 2; successful expensive outputs were reused. No independent scientific input or new algorithm benefit was added.
